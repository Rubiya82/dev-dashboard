## 회사 PC에서 시작하기

공개 코드 개발을 이어가는 경우:

```powershell
git clone https://github.com/Rubiya82/dev-dashboard.git
cd dev-dashboard
git status --short
git log -3 --oneline
git remote -v
```

이미 clone한 폴더라면 먼저 미저장 변경과 현재 브랜치를 확인한다. 작업 트리가 깨끗할 때 `git pull --ff-only`로 갱신한다. 변경이 있거나 분기되었다면 강제로 덮어쓰지 말고 차이를 검토한다.

Codex에서 clone한 저장소 루트를 작업 폴더로 연다. Git 쓰기 인증은 회사 정책에 맞게 별도로 설정한다. 기존 PC의 Git 인증, 로컬 백업, 브라우저 권한, 연결 코드는 clone으로 이동하지 않는다.

실제 회사 데이터 운영은 별도의 사내 저장소/작업 폴더에서 진행한다. 공개 저장소와 운영용 사내 저장소의 원격 주소를 명확히 구분하고, 커밋·푸시 전에 `git remote -v`와 diff를 확인한다. 사내 주소는 아직 제공되지 않았다. 과거 실제 데이터가 포함될 수 있는 기존 PC의 `private-history-before-public` 로컬 브랜치는 공개 원격에 올라가지 않았으며, 새 PC로의 전송 대상이 아니다. `git push --all`이나 `--mirror`를 사용하지 않는다.

## 실행과 저장의 구분

| 사용 방식 | 실행 및 저장 |
|---|---|
| 로컬 기본 | 루트 `index.html`을 Edge/Chrome에서 더블클릭 → 작업 폴더 열기 → 저장소 루트 또는 `web/data` 선택 → 수정 권한 승인 → 편집 → 로컬 저장 |
| Pages | JSON/MD/이미지를 상대경로로 읽음 → 폼 편집 → 변경 ZIP 다운로드 → 저장소 루트에 경로를 유지해 반영 → Git 커밋·푸시 |
| 로컬 Git 자동 반영 | Git + Python 3.10 이상 준비 → `Start-GitHub-Sync.cmd` 실행 → 로컬 HTML에서 연결 코드 입력 → GitHub 반영 → diff 확인 → 저장·커밋·푸시 |

`변경 적용`은 화면 메모리에 반영, `로컬 저장`은 디스크 기록, `GitHub 반영`은 로컬 도구를 통한 원격 전송이다. HTML 내장 샘플은 실제 데이터의 최신 사본이 아니다. 더블클릭 후 실제 데이터를 편집하려면 폴더 또는 Git 도구를 연결해야 한다.

Git 도구는 현재 브랜치의 upstream과 PC의 Git 인증을 사용한다. 버튼 이름이 GitHub 반영이어도 실제 전송 대상은 연결한 저장소의 Git 설정이다. 도구는 데이터 경로만 커밋하므로 앱 소스·문서 변경은 Codex/터미널의 Git으로 커밋·푸시한다.

로컬 도구는 `127.0.0.1`에서 동작하며 `file://` 및 loopback Origin만 허용한다. 공개 Pages에서 이 도구에 직접 연결하는 방식은 지원하지 않는다. 연결 코드는 GitHub PAT가 아닌 실행 시 생성되는 임시 코드이며 저장소나 브라우저 영구 저장소에 자격증명을 저장하지 않는다. 도구 재시작/브라우저 새로고침 후 재연결한다.

## 최근 완료한 기능과 유지해야 할 동작

- 과제 상세 폼에 삭제 버튼을 추가했다. 선택 과제와 모든 하위 작업을 index에서 제거하되 이미 저장된 MD·JSON·이미지는 물리 삭제하지 않는다. 삭제 확정에도 파일 저장/푸시가 필요하다.
- 실제 종료일은 선택 사항이다. 완료 상태로 변경하거나 입력한 날짜를 지운 후 적용해도 오늘 날짜를 자동 입력하지 않는다.
- 보관 필터는 진행 과제만 / 보관된 과제만 / 전체 과제다. 상위 보관 과제의 하위 작업도 보관 범위로 취급한다.
- 사용자가 말한 간트 이동의 본래 뜻은 **과제 순서의 위·아래 재배치**였다. 왼쪽 `⠿` 손잡이를 끌어 같은 부모의 과제 사이에서 순서를 바꾼다. 검색·분류·상태 필터 또는 보관 보기에서는 순서 이동을 제한한다.
- 사용자가 추가로 승인한 **일정 좌우 이동**도 구현했다. 막대를 끌면 시작/목표/실제 종료일 중 값이 있는 날짜를 같은 일수만큼 이동한다. 마일스톤·릴리즈·하위 과제 일정은 자동 이동하지 않는다.
- 간트 종료는 완료 상태에서 실제 종료일이 있으면 그 날짜, 그 외에는 목표 종료일이다. 유효한 막대 일정이 없으면 가짜 날짜를 만들지 않는다.
- 막대 hover/키보드 focus는 현재 상태·진행률·일정·요약과 최근 도메인 기록을 표시한다. 로그·결정·마일스톤·릴리즈 중 날짜가 최신인 기록을 선택하고, 기록이 없으면 변경 이력을 사용한다. 미래 계획도 선택될 수 있어 '마지막으로 수정한 필드'와 동일한 의미는 아니다.
- 폼에서 변경 적용 후 같은 창에서 다시 수정할 때 새 draft에 입력 이벤트가 연결되도록 수정했다.

## 회사에서 우선 확인할 항목과 남은 한계

1. 실제 Edge/Chrome에서 HTML 더블클릭 → 작업 폴더 승인 → 폼 수정/이미지 추가 → 저장 → 다시 열기를 확인한다. 이전 자동 검증은 `file://` 접근 제한 때문에 직접 실행을 확인하지 못했고 폴더 권한·충돌은 API 모형으로 검증했다.
2. 회사의 Python/Git/브라우저 정책과 Git 인증을 확인하고, 가상 데이터용 저장소에서 로컬 도구의 저장·커밋·푸시를 시험한다. 차단되는 경우 폴더 저장 또는 ZIP + 승인된 Git 클라이언트로 운영한다.
3. 실제 사내 운영이 필요하면 사내 저장소 URL·Pages 접근 정책을 확인한다. 외부 공개 저장소는 코드/가상 샘플 용도로 유지한다.

schemaVersion 1과 기존 필드 의미, 알 수 없는 JSON 확장 필드를 보존한다. 날짜 `YYYY-MM-DD`는 달력 날짜로 취급한다. 부모 화면 진행률은 활성 말단 작업의 평균이며 저장된 부모 progress를 덮어쓰지 않는다. MD 폼 관리 영역 밖의 텍스트는 보존하지만 미리보기는 전체 Markdown WYSIWYG가 아니다.

현재 다중 파일 전체 트랜잭션, 실시간 공동 편집, 자동 Git 병합, 브라우저 크래시 복구용 자동 저장은 없다. 외부 파일 변경은 저장 전 비교해 덮어쓰기를 중단한다. 삭제한 기존 파일은 저장소에 남아 URL로 접근할 수 있으므로 삭제 기능을 기밀 제거 수단으로 취급하지 않는다. Git 도구의 `.dashboard-backups`는 로컬 전용이며 clone에 포함되지 않는다. 팀 사용 시 각자 pull → 편집 → push하고 충돌을 명시적으로 해결하는 흐름을 기본으로 한다.
