# 00. Project Brief

현재 제품 목적은 메인 과제와 하위 작업 관리입니다. 최신 설계는 [14_CURRENT_DESIGN.md](14_CURRENT_DESIGN.md)를 참고합니다.

## 1. 배경

개발 업무가 세 종류로 섞여 있어 시간 흐름과 릴리즈 이력을 한눈에 추적하기 어렵다.

1. 수명/수행 받은 업무
2. 개인적으로 개발한 업무
3. 프로젝트로 진행한 업무

각 과제에서 필요한 핵심 정보는 다음과 같다.

- 언제 시작했는가
- 현재 상태와 진행률은 무엇인가
- 어디까지 진행했는가
- 어떤 개발 로그/내부 이력이 있었는가
- 어떤 중요한 결정을 왜 내렸는가
- 언제 어떤 버전을 릴리즈했는가
- 일정이 어떻게 겹쳤는가

## 2. 사용자 경험 목표

메인 화면에서 **간트 + 요약 대시보드**로 전체 작업 흐름을 파악한다. 과제를 클릭하면 상세 화면에서 개발 로그, 의사결정, 마일스톤, 릴리즈를 확인/편집한다.

## 3. 운영 환경

- 사내: GitHub Enterprise
- MkDocs 설치 실패 가능성이 있으므로 v1은 순수 정적 HTML/CSS/JS
- 서버 애플리케이션/DB 없이 Git 저장소가 데이터 원본
- Pages 화면은 읽기뿐 아니라 브라우저 내 편집까지 가능
- 웹 Pages에서 수정한 내용은 파일 다운로드 방식으로 반출
- 로컬에서는 동일 UI를 사용하되 직접 파일 저장을 지원
- 로컬 Git 자동화는 별도 Helper 프로세스로 분리

## 4. 설계 원칙

**Data-first, UI-replaceable.**

카드/간트/타임라인/리포트는 모두 동일한 영속 데이터에서 파생한다. 화면을 나중에 완전히 다시 만들어도 기존 과제 파일은 최대한 그대로 사용할 수 있어야 한다.
